# Knoa 产品力与能力审查

## 结论

Knoa 目前不是“没有能力”，而是能力还没有被包装成用户可以立即感知的结果。Node 已经具备本机 Shell、文件、桌面、浏览器/MCP、Codex、llama.cpp/Vision、任务执行、Artifact 交付和多链路连接；App 也有任务、对话、缓存和结果页。现阶段用户仍需要理解“会话、Task、Agent、Model、MCP、Runtime、Node”等内部对象，才能把这些能力拼成一次成功工作，因此产品看起来像一个很完整的控制台，而不像一个真正的个人助手。

## 与同类产品的用户心智对比

| 产品方向 | 用户输入 | 系统负责的闭环 | Knoa 的机会 |
| --- | --- | --- | --- |
| ChatGPT Agent / Operator | 目标或网页任务 | 规划、浏览器操作、结果说明 | Knoa 可把执行落到用户自己的电脑，并保留本地文件和证据 |
| Claude Computer Use | 目标和操作授权 | 桌面操作、逐步确认 | Knoa 可叠加持久任务、Node 重启恢复和本地模型 |
| Perplexity / 搜索型助手 | 问题 | 搜索、引用、摘要 | Knoa 应把资料搜索后的文件整理、报告生成和后续执行做完 |
| Raycast / 命令型工具 | 命令或快捷动作 | 快速调用单项工具 | Knoa 应用自然语言目标覆盖多步骤工作，并在高风险步骤停下来确认 |
| n8n / 自动化平台 | 工作流编排 | 触发器、步骤、重试 | Knoa 应隐藏编排细节，按个人目标自动选择即时、后台或周期执行 |
| Rewind/记忆型助手 | 过去发生了什么 | 本地检索和回顾 | Knoa 应只保存用户确认过的偏好和可删除的工作记忆 |

## Knoa 当前真正的优势

1. **本机执行边界清晰**：用户的电脑是能力发生地，文件、项目、服务和模型不必上传到第三方。
2. **执行不是一次性聊天**：Task/Execution/Approval/Artifact 已经形成持久状态，可以暂停、恢复、重试并在 Node 重启后继续查看。
3. **证据和交付基础存在**：执行轨迹、失败原因、文件 Artifact 和结果中心可以支撑“做了什么”的可核验交付。
4. **连接韧性有基础**：mDNS、P2P、Relay 已并行建立，并按 `mDNS > P2P > Relay` 选择承载链路。
5. **本地模型组合灵活**：Codex、llama.cpp 和专用 Vision 模型可以按能力和隐私要求组合，而不是绑定单一云模型。

## 当前产品力短板

- 首次连接后没有在一分钟内让用户看到“已经替我完成了什么”；能力入口和结果交付仍偏模板化。
- “整理电脑、维护项目、看懂资料、持续监控”目前主要是目标模板，缺少能力预检、计划预览、执行阶段、证据摘要和撤销/继续按钮的一致闭环。
- 后台通知尚未成为可靠事实源；App 关闭后、飞书/钉钉不在线时，用户可能不知道任务已完成或等待确认。
- 用户偏好、目录规则和审批习惯还没有成为可查看、可修改、可删除的长期记忆。
- 能力页仍主要展示 Agent、Model、MCP、Tool 等内部资源，用户无法快速判断“我现在能让它做什么”。
- 删除会话后的 Hub 工作投影存在残留；已增加签名的投影 reconcile，Node 重启并完成一次同步后会清理旧记录。

## 能力产品化的优先顺序

### P0：可立即证明价值

- 文件整理：扫描范围预览、重复/临时文件分组、移动计划、确认后执行、撤销记录和归档报告。
- 电脑健康：磁盘、端口、Node、模型、网络检查；安全问题一键修复，风险动作明确确认。
- 图片和资料：上传后自动 OCR、分类、提取、比较，输出 Markdown/PDF/表格和来源文件清单；Vision 空结果自动重试。
- 项目维护：定位问题、修改、测试、差异审查、生成交付摘要和可下载补丁。

### P1：让助手持续工作

- 目录、服务、磁盘、模型和网站监控；异常自动收集证据，允许安全修复，失败时通知人类。
- 后台任务通知、审批深链和跨 App/飞书/钉钉一致状态。
- 可查看和撤销的个人记忆：目录命名规则、报告格式、常用项目和审批偏好。

### P2：形成长期护城河

- 基于工作历史的主动预取和建议，但每条建议都说明数据范围和原因。
- 多 Node 协作：手机只需提出目标，系统选择最快且最合适的电脑/模型执行。
- 结果资产化：报告、补丁、归档清单和证据可继续处理、分享和追踪版本。

## 设计验收标准

用户不需要知道 transport、runtime、provider、MCP 或 Agent 的存在。提出一个目标后，Knoa 必须明确显示：

1. 计划做什么、需要访问什么、预计多久；
2. 当前进度、已完成和待确认步骤；
3. 完成了什么、没有完成什么、生成了哪些文件和证据；
4. 失败时原因、影响、可恢复动作和是否可能产生重复副作用；
5. 用户可以继续执行、撤销、分享或删除结果。

这套闭环才是 Knoa 的产品力：不是增加更多内部模块，而是让现有本机执行和可靠状态真正替用户完成工作。
