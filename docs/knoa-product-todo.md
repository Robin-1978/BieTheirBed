# Knoa 产品体验与能力 TODO 清单

> 目标：让用户只需要提出目标，Knoa 负责连接、执行、恢复、交付和通知。
> 范围：Android App、Node、Core、Hub、Relay、mDNS/P2P、Agent/Codex、Vision、任务、审批、Artifact、Console、飞书和钉钉。
> 原则：用户体验优先；正向设计；高内聚、低耦合；YAGNI；不把企业系统作为个人用户的默认路径。

状态约定：`[ ]` 未完成，`[~]` 进行中，`[x]` 已完成。

## P0：不等待、不丢数据、能恢复

### P0.1 App 缓存优先

- [x] 缓存最近会话列表、当前会话摘要、最近消息、草稿、选中 Agent 和未读状态。
- [x] 进入话题时先渲染本地缓存，不等待 Gateway、Hub 或 Node 连接。
- [x] 缓存显示明确新鲜度：刚刚缓存、正在同步、离线、同步失败。
- [~] 远端数据在后台增量同步，不覆盖本地较新的草稿或未发送内容。
- [x] 缓存键隔离 `account + workspace + node + session`，禁止跨账户、跨 Workspace 串数据。
- [x] 首次无缓存时显示可操作空态，不显示无期限 ActivityIndicator。
- [x] 缓存加载失败时保留页面错误和重试入口，不清空已有可读内容。

### P0.2 App 缓存清除与生命周期

- [x] 设置中提供“清除缓存”入口，明确显示缓存占用空间和最近更新时间。
- [x] 支持分别清除：会话消息、会话列表、Workspace 数据、任务/执行记录、文件预览缓存。
- [x] 支持“一键清除全部本地缓存”，不删除账户身份、配对信息、草稿和待发送队列，除非用户明确选择。
- [ ] 提供“清除缓存并退出账户”组合操作，退出账户后清理全部账户作用域数据。
- [~] 删除账户、切换账户、切换 Workspace、移除 Node、重新配对时自动清理对应作用域缓存。（解绑/重新配对已清全部缓存与提醒；切换 Workspace/Node 因缓存键已按作用域隔离而保留）
- [ ] 缓存达到空间上限时按 LRU 清理已完成会话和文件预览，保留草稿、待发送队列和运行中任务状态。
- [ ] 应用卸载、版本升级、缓存版本变化时执行安全迁移或清理旧格式。
- [ ] 清理操作必须可见反馈，失败时说明哪些内容未清理以及重试方式。
- [ ] 清除缓存不得删除服务端数据，不得撤销 Node 配对，不得删除正在执行的后台任务。

验收：有缓存的话题首屏约 300ms 内出现；无网络时仍可阅读和编辑；清除后不再显示旧内容；切换账户后不可见上一个账户数据。

### P0.3 连接与加载状态

- [ ] 所有 Gateway、Hub、Relay、P2P、mDNS 请求统一超时、取消和重试策略。
- [ ] 普通请求失败时间控制在用户可接受范围，长任务改为后台执行，不阻塞页面。
- [ ] 页面状态统一为 `loading / ready / empty / offline / error / retrying`。
- [ ] 进入 Node 立即进入页面，连接在后台完成；连接中提供阶段性文字和操作。
- [ ] App 从后台恢复、网络切换、Node 重启后自动恢复连接，不重复创建会话或任务。
- [ ] 任意错误都包含原因、影响、下一步动作和重试入口。

### P0.4 身份、Workspace 和 Session 隔离

- [ ] 连接状态按账户、Workspace、Node、设备原子隔离。
- [ ] 切换 Workspace 或重新配对时清理旧 Session、事件游标、恢复状态和对应缓存。
- [ ] 不允许旧 Workspace 的会话、任务、提醒或缓存出现在新 Workspace。
- [ ] 认证失效只清理认证会话，不误删有效的用户数据和草稿。
- [ ] 移除 Node、退出账户和重新配对均提供明确确认和结果反馈。

### P0.5 执行前能力预检

- [x] 对文件、Shell、桌面、Codex、llama.cpp、Vision、MCP、凭据和目录做统一预检。
- [x] 预检结果使用用户语言，说明缺少什么、是否可自动修复、修复后影响什么。
- [x] 图片首次分析、Vision 空 observation、Runtime 启动失败和工作目录错误提供可见重试。
- [x] 高风险和未知副作用继续 fail-closed，不因重试或链路切换重复执行。
- [x] 创建即执行（immediate）不绕过预检：定义先建、预检通过才启动（`gateway/routes/tasks.py`）。

### P0.6 全 App 首屏与链路延迟

- [x] 统一定义 App 页面数据策略：本地快照先渲染，网络只负责后台校正，不让页面导航等待远端。
- [~] 覆盖所有用户可见页面，而不只处理会话历史：账户、Workspace 首页、Work、Node 列表、Node 详情、任务列表、任务详情、执行详情、结果、能力、附件、设置和更新页。
- [x] 为每类数据增加带作用域的本地快照：`account + workspace + node + resource`；切换账户、Workspace 或 Node 时禁止串读。
- [x] 所有列表支持 stale-while-revalidate：先显示上次结果，后台刷新时保留内容，只显示轻量“正在更新”状态。
- [~] 所有删除、归档、恢复、重命名和状态操作先更新本地视图，再异步确认；失败时按操作级别回滚并说明原因，不重新阻塞整页。
- [x] 进入 Node、会话、任务和结果详情时先完成导航，连接、权限和详情同步在页面内恢复，不用全屏转圈挡住用户。
- [~] 统一记录每次请求的阶段耗时：页面等待、DNS/TCP/TLS、mDNS 发现、P2P ICE、Relay 握手、业务请求、服务端处理和响应渲染。（已落地：每请求实际承载链路与总耗时记录，设置页“连接质量”展示；握手阶段细分仍缺）
- [x] 统一连接竞速：mDNS、P2P、Relay 并行建立；首个可用链路承载当前请求，后续按 `mDNS > P2P > Relay` 切换；不得为业务请求重复发送有副作用的 POST、PATCH 或 DELETE。
- [x] mDNS 发现不可用时不得阻塞 Relay/P2P；直连探测必须有短超时，失败后立即进入已就绪链路。
- [~] Relay 作为可验证的兜底链路：连接票据、WebSocket、加密握手和业务请求分别计时；Relay 已就绪时不得再次重复握手。
- [x] P2P 建连失败进入短暂冷却并继续使用 Relay；链路恢复后后台升级，不打断正在执行的请求。
- [~] 所有请求有统一的连接超时、业务超时、取消和幂等策略；禁止“请求还在后台但界面一直显示加载中”。
- [~] 页面加载状态统一区分首次加载、后台刷新、离线可读、重试中和失败；只在没有任何可显示内容时使用全屏加载。

验收：冷启动进入任意页面先看到可读内容；已有快照的页面首屏约 300ms 内出现；普通列表操作不因链路握手额外等待数秒；断开 mDNS 或 P2P 时 Relay 能在用户可感知的短时间内接管；无重复删除、重复创建或重复提交。

## P1：能持续执行、能通知、能统一查看

- [~] 统一展示目标、状态、进度、最近活动、待用户决定、结果、文件、证据和恢复操作。
- [ ] 用户无需先判断“新会话还是新任务”，系统根据目标建议即时、后台或周期执行。
- [ ] Chat、Task、Execution、Results、Artifacts 可以从同一工作上下文互相跳转。
- [ ] App、CLI、飞书和钉钉对同一项工作显示一致的最终状态。

### P1.2 后台通知

- [x] Core 持久化 Notification Intent：完成、失败、审批、补充信息、Node 离线、需要更新。
- [x] App 关闭时仍能通过 Hosted FCM 收到系统通知，不依赖 App 在线事件后本地生成通知。（生产投递需配置 FCM/Firebase 凭据）
- [x] 通知去重、重放、过期和点击深链统一处理。
- [x] 通知内容包含原因、影响、可选操作和截止时间。
- [x] 飞书、钉钉、App 和桌面通知复用同一通知事实，不各自猜测状态。

### P1.3 任务和执行

- [x] 任务列表、执行记录、审批和结果默认从缓存展示，再后台刷新。
- [ ] 任务、执行、审批和结果的缓存与会话缓存使用同一作用域、版本、失效和清除机制。
- [ ] 删除或归档任务、执行记录和结果时先从本地列表移除，后台确认后再写入缓存；失败可恢复原状态。
- [ ] 支持暂停、继续、取消、重试、重新执行，并明确潜在重复副作用。
- [ ] 重试成功后进入新 Execution，不制造重复 Task。
- [ ] App 关闭、Node 重启、网络断开后任务继续运行并可恢复查看。
- [ ] 离线创建任务进入可靠待发送队列，恢复后使用幂等键提交。

### P1.4 对话与媒体

- [ ] 进入会话不等待远端历史；本地缓存和服务器 revision 增量合并。
- [ ] 会话列表、会话摘要、消息、草稿、待发送队列和附件预览分别缓存，不能因为某一项同步失败清空其他可读内容。
- [ ] 删除会话、清除本地缓存和服务端删除明确区分；本地清除不得隐式删除服务端会话。
- [x] 运行中回复支持停止；失败或取消支持重试、编辑后重发。
- [x] 用户向上阅读时不被自动滚到底部，提供回到最新操作。
- [~] 附件逐项显示准备、上传、完成、失败和重试状态。（Chat 附件已逐项展示并可重试；任务创建附件为一次性批量上传）
- [ ] 大文件上传支持取消、进度和失败后精确重试。
- [ ] 语音录音、上传、转写失败时保留录音并提供重试或删除。
- [ ] 图片预览、保存到相册、保存文件和分享语义明确区分。

### P1.5 首次使用与默认内容

- [ ] 首次路径收敛为“连接电脑 -> 自动检查 -> 直接提出目标”。
- [ ] 默认隐藏 Workspace、Node、Transport、Runtime、Provider 等内部名词。
- [x] 默认示例只保留文件整理、代码维护、图片分析、资料总结和个人报告。
- [x] Jira、GitLab 等企业连接移入可选扩展，不出现在新用户默认会话和任务模板。
- [ ] 首次任务创建前解释通知、权限和可能副作用。

### P1.6 个人助手能力包（产品力）

- [ ] “整理我的电脑”：扫描下载目录和指定文件夹，先给出可预览计划，再批量归档、重命名、去重和生成撤销记录。
- [ ] “帮我维护项目”：从问题定位、代码修改、测试、差异审查到交付文件形成一条可追踪工作，不要求用户自己拼接 Agent、Model、MCP 和 Runtime。
- [ ] “看懂图片和资料”：手机拍照或上传文件后，自动提取信息、分类、总结、比较并产出 Markdown、PDF 或表格，不只返回一段聊天文本。
- [ ] “持续帮我盯着”：对目录、服务、磁盘、模型、网络、网站或周期性资料建立可暂停的监控任务，异常时自动尝试修复并通知用户。
- [ ] “远程处理电脑”：用户在手机、飞书或钉钉下达目标，Node 在本机执行 Shell、桌面、浏览器、Codex 和本地模型能力，结果带证据和文件链接返回。
- [ ] “记住我的做事方式”：保存用户明确确认过的偏好、目录规则、命名规则和审批习惯；可查看、修改、删除，不把未经确认的推断写成长期记忆。
- [ ] 每个能力包都提供一句话入口、示例输入、预计耗时、需要的权限、风险等级、进度、结果和失败恢复，不把内部配置页当作能力入口。
- [ ] 能力包支持即时执行、后台执行和周期执行三种模式；用户只说目标，系统根据耗时、风险和是否需要持续观察自动选择并允许修改。
- [ ] 能力包结果必须包含“完成了什么、没有完成什么、生成了什么、下一步是什么”，并可一键打开、分享、下载或继续处理。

产品验收：新用户在首次连接后 60 秒内能完成一次文件整理、图片理解或项目维护；不需要理解 transport、runtime、provider、MCP 等内部概念；每个能力都有可见结果而不是只展示聊天回复。
