# Knoa 个人数字员工与下一代体验设计

> **版本**: 0.1
> **日期**: 2026-09-05
> **状态**: 设计中

---

## 1. 概述

### 1.1 文档范围
本文档针对 Knoa 客户端及协同中枢体系从传统聊天助理（Chatbot / Copilot）向全天候个人数字员工（Personal Digital Co-worker）跨越演进进行顶层设计。涵盖产品定位、随身指挥终端交互升维、桌面感知微缩窥探（Desktop Glance）、Bento Box 三维任务看板、成果陈列资产消费、以及可审计透明记忆工坊（Transparent Memory Bank）的设计规范。

### 1.2 设计目标
1. 消除空白感知与启动断层：彻底解决初次配对后面对空白输入框的冷启动障碍，在用户连入电脑 60 秒内通过主机探针主动呈现环境健康与待办卡片，建立明确确定性。
2. 跨越黑盒运行与恐惧感：将传统后台任务中单调的字符进度转变为包含真机状态、实时桌面微缩预览图（Live Glance）与可审计步骤的透明流水线，使用户随时掌控真机动态。
3. 强化确定性与安全边界：在 Stochastic-Deterministic Boundary (SDB) 与人机回环（HITL）机制上，提供包含影响面、回滚计划与一键决策的结构化拦截卡片，杜绝高风险外部副作用破坏用户环境。
4. 沉淀战果与认知复利：打通任务结果与会话产物，建立成果陈列室，并利用 Scoped SQLite 存储机制打造用户可查、可改、可删的透明记忆工坊，形成越用越懂用户的长期留存飞轮。

### 1.3 术语定义
- Digital Co-worker（数字员工）：具备目标理解、真机执行、SDB 安全门禁、长效自愈与成果交付完整闭环的个人智能体。
- Desktop Glance（桌面微缩窥探）：利用宿主端 Screen 观察能力定时捕获并降采样生成的桌面状态缩略图，用于移动端无感感知。
- Bento Box 看板：按照作业状态（运行中、待裁决、已收官）三维划分的现代化不对称卡片控制台。
- Actionable HITL（交互式人机拦截）：高危动作触发挂起时，跨设备直接提供具备上下文说明与内联确认的决策界面。
- Transparent Memory Bank（透明记忆工坊）：直接映射底层 SQLite MemoryRepository 的用户可见、可编辑的结构化事实与偏好集合。

## 2. 系统架构

### 2.1 现状架构与体验瓶颈
经过前期 v0.2.104 版本的重构，应用已经收敛了底部导航体系，解决了键盘避让、跨节点通知干扰以及基础的 Slash 快捷指令与资产全文检索。然而，从虚拟员工的产品定位审视，仍存在以下体验瓶颈：
1. 会话首页依然以单向文本流为主，缺乏开箱即用的主动环境感知，用户在没有明确 Prompt 时难以驱动数字员工展开工作。
2. 任务执行状态虽有步骤序列，但用户无法直观了解当前电脑正在发生什么，缺乏对物理桌面和前台软件的即时视觉确认。
3. 记忆系统在底层具备 SQLite 存储和 Core API 协议（`src/knoa_platform/context/memory_db.py:79-120` 与 `src/knoa_platform/service/core_api.py:1103-1110`），但表现层尚未将其产品化，用户对智能体记住什么毫无感知且无法纠偏。

### 2.2 下一代数字员工目标架构
重构后的系统分为三层协同架构：随身指挥终端、协同领域与安全门禁中枢、以及宿主实体与多模态执行底座。

![下一代数字员工目标架构图](images/06_coworker_target_architecture.svg)

### 2.3 核心组件概要
1. 随身指挥终端（Mobile Command Deck）：
   - Chat Command Deck：集成灵动设备胶囊（实时展示网络/算力/模型）、剪贴板即时联想浮条、以及首屏动态环境诊断建议流。
   - Bento Tasks Hub：采用非对称 Bento Box 布局，将进行中任务、待批准事项（HITL）和历史完成态按优先级分栏呈现，支持就地启停与桌面微缩视窗。
   - Trophy Showcase（数字战果陈列室）：以卡片瀑布流呈现代码补丁、调研简报、图片图表与归档目录，支持跨模态全文检索与一键分享。
   - Memory & Fleet（透明记忆与机甲库）：展示绑定电脑的硬件负载、可用 MCP 工具库雷达，并提供可视化个人记忆条目管理器。
2. 协同领域与安全门禁中枢（Domain & SDB Gateway Layer）：
   - Durable Task 状态机：支持 Attempt 增量检查点与进程崩溃自愈，确保移动端离线状态下任务不中断。
   - SDB 确定性安全门禁：拦截写操作、文件删除与系统命令，对高危动作实施 fail-closed 并构造跨端推送意图。
   - 成果聚合与证据交付引擎：统一对接 Artifact 流，生成带格式、来源、耗时与节约时间的标准化结果报文。
   - Scoped Memory 适配层：将用户交互事实分类为核心习惯（core）与关联上下文（relevant），校验置信度并向端侧暴露 CRUD 接口。
3. 宿主实体与多模态执行底座（Node & Execution Foundation）：
   - Split Vision 本地感知：利用宿主轻量视觉模型（Qwen-VL）及 Screen 截图工具，定时采集桌面微缩图像并进行要素解析。
   - 真机执行环境：提供受控 Shell、本地文件系统操作、窗口聚焦及键鼠自动化驱动。
   - 扩展沙箱：通过 MCP 客户端与 Skill 运行时隔离第三方系统依赖。
   - 私有记忆数据库：宿主端本地 SQLite 存储，保证隐私不出本地。

## 3. 核心流程与场景

### 3.1 场景一：开箱即用 60 秒极速体检与主动建议（Zero-Shot Aha Moment）
用户进入应用或切换至已绑定电脑时，系统自动触发轻量探针收集宿主状态。
1. 移动端建立网关连接后，向 Core 发送探测指令。
2. Node 采集当前主机指标（磁盘余量、下载目录未归档堆积数、仓库待同步变更）。
3. 端侧若检测到会话处于冷启动阶段，在输入区上方动态生成 3 条可直接触发的建议卡片（如清理大文件、归拢桌面截图、同步 Git 分支）。
4. 用户单触确认后，直接以预填参数启动 Durable Task，跳过表单填写与提示词调试。

### 3.2 场景二：后台长任务运行、桌面微缩窥探与断线自愈（Durable Execution & Glance）
数字员工执行多步复杂作业时的持续反馈链路。
1. 任务创建时分配全局唯一 TaskId 与初始 AttemptId。
2. 执行过程中，Node 按照预设间隔（如 10 秒）或关键工具调用节点触发 `screen` 工具，生成经压缩的 320x180 像素桌面快照（Desktop Glance）。
3. 移动端 Bento 看板实时接收快照流并以内联缩略卡呈现，点击即可放大核验当前软件运行画面。
4. 移动端网络中断或 App 进程被操作系统冻结时，Node 保持执行；移动端重连后通过序列号回放增量事件，保持端侧进度与真机完全同步。

### 3.3 场景三：高风险动作拦截、富卡片决策与人机协作（Actionable HITL）
作业涉及系统写入或不可逆修改时的安全交互流程。
1. Agent 推理生成包含高危影响（如覆盖代码、批量删除、敏感网络请求）的工具调用。
2. SDB 门禁在宿主端挂起当前 Attempt，并将调用上下文、影响文件列表、可撤销性评定打包为 ApprovalRequest。
3. Core 产生持久化 NotificationIntent，并向移动端推送高优先级决策卡片。
4. 移动端以警示琥珀色横幅及浮窗展现影响面与建议动作；用户直接在端侧点击批准或驳回。
5. 门禁验证签名凭证后恢复任务执行或回滚草稿。

### 3.4 场景四：透明个人记忆沉淀、审计与偏好检索（Transparent Memory Bank）
数字员工自我进化与偏好管理的透明化链路。
1. 在多轮对话或任务完成时，Agent 根据明确的用户纠偏或约定（如常用项目路径、报告排版要求）提取偏好键值。
2. 偏好信息写入宿主 SQLite 数据库，标记分类与置信度。
3. 移动端控制中心提供专属「记忆工坊」面板，以扁平卡片列表分页展现全部已记录事实。
4. 用户可对任何一条推断事实进行编辑、标记无效或物理删除；被删除的记忆在后续 Prompt 注入时立即被排除。

### 3.5 异常与失败处理
针对核心交互链条中的外部调用异常，统一规范失败行为、级联影响与用户可见表现：

| 交互环节 | 外部调用 | 失败行为 | 上下游影响 | 用户可见表现 |
|:---|:---|:---|:---|:---|
| 开箱诊断 | 探针采集接口 | 3 秒超时放弃，降级为静态快速模板 | 无法获取动态机器指标，不影响正常会话启动 | 呈现标准建议胶囊，顶部提示已读取离线缓存 |
| 桌面窥探 | 截图捕获 (mss/Pillow) | 捕获失败或环境无图形界面时静默跳过 | 任务正常执行，仅暂停发送微缩快照 | Bento 卡片内微缩窗切换为步骤文字流水线 |
| 人机审批 | 跨端推送通道 | 降级至本地持久化队列，等待主动轮询 | 任务在宿主端安全挂起，不发生未授权写入 | 任务看板常驻待裁决警示状态，附带红色操作角标 |
| 偏好管理 | 记忆数据库读写 | 触发事务回滚，记录错误审计日志 | 本次会话不持久化该偏好，不影响当前任务产出 | 记忆面板提示同步暂缓，保留本地临时状态 |

## 4. 数据协议与接口定义

### 4.1 数据结构

#### 桌面微缩快照（DesktopGlanceRecord）
用于端侧任务看板展现真机画面微缩预览。
- `taskId`: 任务唯一标识符（字符串）
- `attemptId`: 当前执行尝试标识（字符串）
- `timestamp`: 采样时间戳（毫秒数）
- `thumbnailBase64`: JPEG 格式低分辨率图像编码（字符串）
- `windowTitle`: 当前活动窗口标题（字符串）
- `activeApp`: 当前前台应用程序名称（字符串）

#### 记忆条目实体（MemoryRecord）
对应底层 `src/knoa_platform/agent_runtime/contracts.py:53-60` 契约规范。
- `key`: 偏好唯一标识名（字符串）
- `value`: 记忆具体内容事实（字符串）
- `category`: 归属业务分类，如 environment、workflow、preference（字符串）
- `importance`: 重要程度枚举，取值为 core 或 relevant
- `confidence`: 推理置信度，浮点数，范围 0.0 至 1.0
- `source`: 来源标识，记录由哪次回合或任务触发提炼（字符串）

#### Bento 看板卡片模型（TaskBentoCard）
聚合展示作业状态的端侧视图对象。
- `taskId`: 任务标识
- `title`: 任务目标名称
- `phase`: 作业阶段，枚举：active（狂飙中）、waitingApproval（等待裁决）、completed（今日收官）
- `progressStep`: 当前执行步骤序号与总步骤描述
- `latestGlance`: 关联的最新 DesktopGlanceRecord（可选）
- `savedMinutes`: 预估节省人力时长（整数，单位分钟）
- `pendingApproval`: 关联的审批上下文详情（可选）

### 4.2 接口定义

#### 记忆管理接口（Gateway 路由扩展）
- 查询记忆列表：
  - 请求：`GET /v1/memories?category={category}&importance={importance}`
  - 响应：`{ items: MemoryRecord[], total: number }`
- 更新或补充记忆：
  - 请求：`PUT /v1/memories/{key}`
  - 请求体：`{ value: string, category: string, importance: "core" | "relevant" }`
  - 响应：`{ item: MemoryRecord, updated: boolean }`
- 删除指定记忆：
  - 请求：`DELETE /v1/memories/{key}`
  - 响应：`{ key: string, success: boolean }`
- 清空记忆库：
  - 请求：`POST /v1/memories/clear`
  - 响应：`{ cleared: boolean }`

#### 桌面即时窥探接口
- 获取最新微缩快照：
  - 请求：`GET /v1/tasks/{taskId}/glance`
  - 响应：`DesktopGlanceRecord`
  - 错误码：`404 NotFound`（无活动窗口或未开启桌面会话）

### 4.3 消息定义
通过网关现有 SSE / WebSocket 实时广播：
- `task_glance_updated`: 广播最新桌面快照变更，载荷包含 `DesktopGlanceRecord`。
- `memory_mutated`: 广播记忆库条目变动，载荷包含变动动作（create/update/delete）与对应条目。
- `hitl_approval_required`: 广播高危动作拦截事件，载荷包含挂起 ID 与影响评估元数据。

## 5. 设计决策记录（ADR）

### 决策 1：从打字机式对话升维为主动作业的数字员工
- **背景**：现有聊天式会话要求用户先理解 Prompt Engineering，在手机小屏幕上频繁输入长文本体验糟糕；用户需要的是直接解决问题的虚拟员工而非聊天对象。
- **选项**：
  - 选项 A：继续优化 Chat 气泡与更多输入框快捷指令。
  - 选项 B：保持 Chat 底座的同时，升级为「主动诊断建议 + 意图一键转任务」的双驱模式。
- **决定**：选择选项 B。
- **后果**：新用户在打开应用第一秒即可点击卡片开始任务，大幅提升产品初次启动的转化率和获得感。

### 决策 2：任务控制台升级为 Bento Box 三维状态看板
- **背景**：原任务列表（`app/tasks/index.tsx`）采用平铺列表呈现所有状态的任务，导致正在执行的任务与已结束的历史任务视觉权重相同，关键审批事项容易被淹没。
- **选项**：
  - 选项 A：在现有单列列表中增加过滤标签。
  - 选项 B：重构为现代 Bento Box 视觉层次，置顶进行中大卡片与待裁决琥珀色卡片，历史任务自动沉淀。
- **决定**：选择选项 B。
- **后果**：形成强烈的工作台质感，用户一眼就能掌握当前正在跑什么、需要自己拍板什么。

### 决策 3：引入基于本地感知工具的桌面微缩窥探（Desktop Glance）
- **背景**：手机指挥后台电脑时，用户最大的焦虑是无法感知电脑当前的真实界面状态，盲盒式等待容易导致对 Agent 的不信任。
- **选项**：
  - 选项 A：搭建高带宽实时远程桌面视频流（如 WebRTC / VNC）。
  - 选项 B：复用现有本地 `screen` 工具与压缩管道，以极低带宽（每帧约 15KB）定期向移动端推送静态微缩快照。
- **决定**：选择选项 B。
- **后果**：实现极高质感的真机控制感，同时避免在蜂窝网络下产生巨大的流量开销和手机电量损耗。

### 决策 4：透明化个人记忆工坊替代黑盒推理偏好
- **背景**：大模型推断的用户偏好如果完全封闭在后台，一旦产生幻觉或错误假设，用户无法纠偏，将严重损害长期信任。
- **选项**：
  - 选项 A：仅由系统在 Prompt 中隐式注入历史摘要，不向端侧展示。
  - 选项 B：在端侧提供专属透明记忆看板，将 SQLite 中的 Scoped Memory 直接转化为可由用户手动审计、删除和编辑的卡片。
- **决定**：选择选项 B。
- **后果**：消除用户对个人隐私被随意记录的疑虑，让数字员工的个性塑造完全受主人掌控。
