# Knoa 个人助手与虚拟员工产品策略

## 产品定义

Knoa 是用户可以远程指挥的个人虚拟员工：用户只描述结果，Knoa 负责理解目标、选择合适的电脑和能力、预检权限、制定计划、执行多步工作、在风险点请求确认、保存证据、交付文件，并在用户不在线时继续运行和通知。

“虚拟员工”不是把聊天窗口改名，而是具备以下工作属性：

- 有明确的工作目标和完成标准；
- 能使用用户授权的电脑、文件、项目、浏览器、模型和服务；
- 能运行数秒到数小时，暂停、恢复、重试和在 Node 重启后继续；
- 对有副作用的动作先给计划或请求确认；
- 完成后交付结果、文件、证据和下一步，而不是只输出一段文本；
- 能被 App、桌面、CLI、飞书和钉钉以同一个工作状态查看。

## 用户承诺

用户永远从目标开始：

> “整理我的下载目录。”
> “把这个项目修好并告诉我改了什么。”
> “看懂这批图片，生成报告。”
> “每天早上检查电脑和服务，异常时提醒我。”
> “研究这个问题，给我一份有来源的行动简报。”

Knoa 必须让用户看到四个答案：现在做什么、在哪里做、还需要多久、最后交付什么。

## 能力地图

### 个人电脑执行

文件扫描、读取、归档、重命名、去重、撤销记录；Shell、端口、进程、日志、服务和系统健康检查；桌面、窗口、鼠标、键盘、剪贴板和截图；浏览器/MCP；本地项目维护和测试。

### 认知与资料

网页搜索和抓取、文档/PDF/图片提取、Vision 观察、OCR、总结、比较、结构化表格、Markdown/PDF 报告、来源和不确定性标记。

### 工程交付

项目定位、代码修改、测试、差异审查、补丁和交付摘要；Codex 作为可选的工程 Agent，本地模型作为隐私和成本可控的推理能力。

### 持续工作

定时任务、目录/服务/磁盘/模型监控、异常证据收集、可暂停修复、审批、通知、失败恢复和结果历史。

### 记忆与偏好

只保存用户明确确认的目录规则、命名规则、报告格式、项目和审批偏好；所有记忆可查看、修改和删除，不把推断写成事实。

## 正向架构

领域边界保持单一所有者：

- Core 负责工作、会话、执行、审批、通知事实和持久状态；
- Node 负责本机能力、运行时、模型、文件和桌面执行；
- Hub 负责账号、Workspace、Node 目录、共享资源和只读工作投影；
- App 负责目标输入、缓存优先呈现、进度、确认、结果和通知交互；
- Feishu/DingTalk/CLI 只渲染同一 Notification Intent 和 User Work，不复制业务状态机；
- mDNS、P2P、Relay 是可替换传输实现，不渗透到工作领域模型。

每项能力遵循统一契约：

```text
目标 -> 作用域/执行 Node -> 预检 -> 计划 -> 风险确认 -> 执行 -> 证据/Artifact -> 结果 -> 继续/撤销/分享
```

能力包只负责把用户目标翻译成领域任务和预检，不创建第二套任务系统，不引入通用 Workflow DSL。

## 发布阶段

### 第一阶段：证明“能干活”

文件整理、电脑健康、图片/PDF 资料、项目维护、网页调研简报全部具备用户入口；任务创建必须选择执行 Node；首屏使用缓存，连接后台竞速；结果页显示完成项、未完成项、文件和证据。

### 第二阶段：证明“能持续工作”

后台 Notification Intent、App 关闭通知、审批深链、暂停/继续/取消/重试、目录和服务监控、离线待发送队列、Node 重启恢复。

### 第三阶段：证明“像员工一样协作”

可审计的个人记忆、周期报告、多 Node 选择、根据目标自动选择即时/后台/周期模式、跨渠道统一工作状态、结果资产版本和继续处理。

## 产品门禁

- 新用户首次连接后 60 秒内完成一个小目标并看到可下载结果；
- 任何任务都显示执行 Node 和权限范围；
- 高风险写入没有确认不能发生，重试不会重复副作用；
- App 关闭、断网或 Node 重启后任务状态可恢复；
- 失败页面说明原因、影响、恢复动作和缺失证据；
- 不向普通用户展示 transport、runtime、provider、MCP 等内部术语；
- 默认内容面向个人电脑和个人工作，不展示企业 Jira/GitLab 模板；
- 发布必须验证 Android 版本、APK SHA256、Node 运行版本、Hub 健康、mDNS/P2P/Relay 和 Vision 首次请求。

## 当前实现映射

当前代码已经具备缓存优先、链路竞速、任务/执行/Artifact、个人能力入口、Vision 空结果重试、Vision 输出预算修复、执行 Node 选择和 Hub 工作投影 reconcile；2026-08-23 起结果中心结构化回答“完成/未完成/证据/下一步”，任务启动前预检警告需要用户确认，通知文案如实标注“App 运行期间送达”。下一批工作的重点是后台通知事实源、任务创建页内联预检、请求阶段耗时打点、监控任务闭环和可管理的个人记忆，而不是增加更多内部配置页。
