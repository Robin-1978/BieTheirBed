# 小诺 Mobile 产品体验打磨计划

> 日期：2026-08-11  
> 状态：已完成并发布  
> 范围：Android App 的界面、交互、可理解性、稳定性与无障碍  
> 原则：从用户目标出发正向设计；不保留错误的旧交互；内部模型和技术细节默认不暴露。

## 1. 总体判断

小诺 Mobile 已具备稳定的产品骨架：对话、实时执行、权限确认、图片与文件、持久会话、
任务与执行记录、通知、主题、多语言和私有更新均已形成闭环。当前主要差距不再是功能有无，
而是高频交互的稳定性、普通用户的理解成本，以及不同页面之间的视觉和反馈一致性。

本轮保留以下产品方向：

- `Task -> TaskExecution -> ExecutionAttempt` 领域模型不变；App 只展示任务和执行记录；
- 顶部使用对话、任务两个纯图标入口，设置保持唯一入口；
- 延续暖米色、玉石绿的安静私人助理主题，不改成蓝紫霓虹科技风；
- 用户消息立即出现，执行步骤实时更新，工具调用在同一行从进行中更新为完成；
- 图片支持缓存预览、缩放、保存到相册和分享；文件明确区分打开与保存。

## 2. P0：使用稳定性与信任

### 2.1 聊天滚动

当前内容高度变化可能重复触发滚动到底部。执行步骤展开、工具完成和最终答案插入时，容易
产生上下抽动或停在上一条消息。

目标行为：

- 首次进入会话无动画定位最新内容；
- 用户位于底部时才跟随实时内容；
- 用户主动向上阅读后不抢滚动位置，并提供“回到最新”；
- 用户发送消息只触发一次平滑滚动；
- 加载更早消息时保持当前可见内容的位置；
- 最终答案替换执行中内容时不重新启动滚动动画。

### 2.2 用户反馈语义

成功、提示、警告和错误不得共用红色错误条。统一短消息模型：

- 成功：中性或绿色，自动消失；
- 提示：中性，可自动消失；
- 警告：暖黄色，必要时提供动作；
- 错误：红色，保留到用户关闭或重试；
- 连接与强制更新：使用持久横幅。

### 2.3 新话题事务性

新话题在本地准备成功前不破坏当前会话。失败时保留原消息、草稿和附件；只有用户发送首条
消息后才在服务端形成真实会话记录。

### 2.4 配对与二维码过期

主流程只要求用户扫描电脑上的二维码。页面说明二维码是短时、单次使用，并把 CLI 命令、
原始 `pairing_json` 收进“其他连接方式”。认证过期时使用可理解的恢复文案，允许立即重新扫码。

### 2.5 主题切换

浅色、深色、跟随系统必须即时生效，Activity 重建时不丢失草稿、不进入启动循环。发布前需要
真机覆盖聊天执行中、键盘展开、图片预览、冷启动和低内存恢复。

### 2.6 多语言完整性

所有用户可见文字进入统一 i18n，包括任务、执行详情、会话、配对、图片、更新、权限、通知和
错误提示。语言切换后当前页面立即重渲染，不出现中英文混搭。

## 3. P1：效率与可理解性

### 3.1 任务创建渐进披露

默认只展示“做什么、什么时候做、是否重复、怎样通知”：

- 立即执行；
- 指定时间；
- 每天；
- 每周；
- 固定间隔。

Cron、时区和事件来源进入高级设置。创建前显示自然语言启动摘要，例如“每天 18:30，使用
北京时间”。

### 3.2 执行详情分层

默认展示状态、目标、结果、时间、文件和操作。任务 revision、不可变快照、原始参数、错误码、
完整步骤进入可折叠“技术详情”。聊天与任务执行共用相同的工具时间线合并规则。

### 3.3 主页面切换

对话和任务切换不使用“旧路由退场、下一路由淡入”的两段动画；移除透明度闪动，保证左右方向
一致。长期目标是同一 Pager 容器保留两页状态。

### 3.4 按钮与异步操作

- 图标按钮触下立即改变背景；
- 主按钮立即改变颜色，异步期间在原位置显示进度；
- 列表行使用 ripple；
- 所有触控区域至少 44x44；
- 不可逆操作才使用危险色；
- 禁止整页等待代替局部反馈。

### 3.5 会话列表

使用虚拟列表支持长期积累；默认按最近活动排序。重命名、归档、删除收敛为次级操作，当前会话
和运行中会话有明确状态。

### 3.6 文件性能

大文件下载和保存应有局部进度并允许继续浏览。避免不必要的 Base64 中间副本；图片预览缓存与
用户主动保存是两个不同状态。

## 4. P2：视觉、品牌与无障碍

- 浅色模式次要文字达到 WCAG AA；12-13px 文本不得依赖低对比度；
- 图标统一 outline 视觉重量；设置使用 outline；历史和时间使用不同图标；
- 新话题使用“对话气泡 + 加号”语义，不使用突兀的实心圆加号或尖锐笔形；
- 停止使用灰绿色中性状态，不默认使用红色；
- Markdown 粗体与正文同字号，只提高字重；
- 动画支持系统“减少动态效果”，Splash 不人为延长启动；
- 空状态包含一句说明和一个明确主操作；
- 图标按钮提供无障碍名称、选中状态和足够点击区域。

## 5. 实施顺序

1. 聊天滚动、反馈语义、新话题和文件交互；
2. 配对、主题、多语言和视觉基础组件；
3. 任务创建、任务详情、执行详情和统一时间线；
4. 主页面切换、会话列表、按钮与无障碍；
5. 自动化验证、真机关键路径、签名 APK、私有发布、提交与推送。

## 6. 发布验收

- 发送文字后立即出现，实时步骤更新期间不发生上下抽动；
- 向上阅读时不会自动回到底部，“回到最新”可恢复跟随；
- 成功保存文件不会显示红色错误提示；
- 权限确认只可提交一次，提交中不可重复点击，完成后卡片消失；
- 图片可预览、缩放、保存和分享，文件可选择目录保存；
- 新话题不会提前创建服务端空记录；
- 会话默认最近优先，打开后定位最新消息；
- 任务创建不要求普通用户理解 Cron；执行详情默认不暴露内部 revision 和 JSON；
- 中英文模式无混搭；浅色、深色切换不崩溃；
- 对话和任务的点击、滑动方向一致且无闪白；
- `npm test`、`npm run typecheck`、Python 全量测试和签名 APK 构建通过。
