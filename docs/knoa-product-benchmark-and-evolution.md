# Knoa 产品能力与体验基线

更新：2026-08-23

这份文档把“小诺是能替人工作的个人助手/虚拟员工”作为产品基线，并将内部技术概念与用户体验明确分层。

## 1. 能力对比

| 产品方向 | ChatGPT / Claude / Gemini | Devin / Cursor / Claude Code | Zapier / Notion AI | Knoa 应达到的结果 |
| --- | --- | --- | --- | --- |
| 目标入口 | 描述目标、项目或任务 | 描述工程目标 | 配置自动化 | 用户只描述要达成的结果，不必先理解 Node、Agent 或 MCP |
| 执行边界 | 云端工具、浏览器和文件 | 代码仓库、终端、测试 | 连接器和工作流 | 在用户自己的电脑上执行文件、代码、桌面、模型和外部工具 |
| 持续工作 | 任务、后台研究、通知 | 长任务和检查点 | 触发器和重试 | 断线可恢复、后台继续、完成/失败/需确认时通知人 |
| 结果交付 | 文本、文件、引用 | PR、补丁、日志 | 工作流记录 | 结果、文件、证据、执行记录和下一步动作一起交付 |
| 风险控制 | 确认、权限和沙箱 | 代码审查和隔离 | 步骤级权限 | 高风险操作预览、审批、幂等、可恢复；权限边界不可自我放宽 |
| 扩展 | GPT/Project/Connector | 插件和工具 | App/Action | Skills 与 MCP 一键导入、预检、版本化和回滚 |

Knoa 的核心差异不是再做一个聊天窗口，而是“手机远程指挥 + 用户电脑实际执行 + 本地模型和外部工具组合 + 可交付结果”。短板集中在入口收敛、后台工作通知、失败自愈、扩展导入和结果证据链。

## 2. App 信息架构基线

普通用户只需要看到五个任务入口：

1. 新工作：描述目标、选择（或接受默认）执行电脑。
2. 进行中：查看正在执行、等待确认和最近失败的工作。
3. 结果：查看文件、证据、链接和可继续执行的后续动作。
4. 我的电脑：查看可用电脑及其能力，用人能理解的电脑名称标识。
5. 设置：帐号、通知、缓存和高级诊断。

以下术语默认只在高级诊断或能力管理中出现：`node_id`、Gateway、Transport、Runtime、Provider、MCP、Skill、Agent。用户界面不得把协议 ID 当作名称；名称缺失时显示“未命名电脑”，原始 ID 仅用于复制、排障和支持。

## 3. 连接与缓存体验指标

- 首屏先读本地缓存，再后台刷新；缓存内容必须标记同步时间和来源。
- 连接建立采用并行候选，谁先成功先提供服务；后续按 mDNS > P2P > Relay 迁移，不阻塞当前业务。
- 会话列表、历史、任务、Workspace 目录和资源页都使用同一套缓存/刷新状态组件。
- 删除、发送、切换 Node 等操作使用本地乐观状态和可重试队列；失败时恢复并给出明确原因。
- 目标：已有缓存页面首屏小于 300ms；在线刷新不阻塞导航；操作反馈在 100ms 内出现。

## 4. GitLab retry 根因与修复

GitLab 权限和 MCP 服务均正常。失败发生在审批恢复：同一 Task 的第二次 durable execution 复用了 Task ID 作为 Runtime operation ID，Runtime 将其识别为已持久化的重复 operation，抛出 `turn_outcome_requires_reconciliation`，因此尚未稳定调用 GitLab retry API。

修复保留 `turn_id=task_id` 作为任务、审批和审计关联，同时为每次执行使用 `task_id:attempt:N` 作为 `operation_id`。这样审批恢复和显式重试拥有独立的 Runtime 幂等键，且不破坏领域关联；回归测试验证了 attempt 递增和稳定的 Task ID。

## 5. 安全的自我进化闭环

```text
用户反馈/失败证据
→ 脱敏样本与失败分类
→ 离线评测集
→ Prompt、Skill、路由、模型或恢复策略候选
→ 沙箱回放与安全/成本/回归评测
→ 人工批准
→ 灰度发布、指标监控、可回滚
```

允许自动提出候选的范围：Skill 内容、工具路由、提示词、失败恢复、缓存参数、模型 fallback 和能力说明。禁止自动修改权限上限、审批策略、凭据、隔离边界、部署脚本或外部副作用工具的安全等级。每次改进都应有版本、评测证据、灰度范围和回滚点。

## 6. 验收清单

- 任意普通页面不直接展示 Node ID。
- 未命名或历史绑定显示“未命名电脑/Unnamed computer”。
- 高级诊断可复制原始 Node ID 和 Gateway。
- GitLab 审批恢复不会因为重复 Runtime operation 直接失败。
- 移动端类型检查、单元测试和 Python 定向测试通过。
- 发布包、Node 部署和版本信息保持一致。
